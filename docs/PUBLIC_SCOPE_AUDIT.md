# 공개 범위 재검토

검토 기준일: 2026-09-08. 목적은 개인 운영 자료와 권리 확인이 안 된 외부 자료를 제외하면서, 프로젝트의 구현과 기술 설명을 가능한 한 보존하는 것입니다.

## 비교 방법과 결과

원본 현재 작업 트리의 Git 관리 파일과 무시되지 않은 신규 파일을 공개본의 추적 파일 목록과 대조했습니다. 이전 내보내기에서 보관한 원본 해시도 현재 파일과 비교했습니다. 아래 공개본 수치는 **이번 소개 문서 3개를 추가하기 전** 기준입니다.

| 범위 | 원본 파일 | 공개본 파일 | 원본 중 누락 |
|---|---:|---:|---:|
| `app/` | 371 | 371 | 0 |
| `tests/` | 376 | 377 | 0 |
| `backtester/` | 49 | 49 | 0 |
| `scripts/` | 15 | 16 | 0 |
| `config/` | 3 | 3 | 0 — 운영 프로필 내용은 예제로 대체 |
| `docs/` | 156 | 129 | 27 — 개인 운영·작업 기록 |

테스트와 스크립트의 추가 파일은 공개본 격리와 무결성 검증을 위한 것입니다. 이전 내보내기에서 기록한 포함 대상 원본 파일의 해시 변경은 0건이었습니다. `app/`, `tests/`, `scripts/`, `docs/`에서 Git 무시 규칙 때문에 빠진 Python·셸·Markdown·노트북 소스도 없었습니다. 백테스터에서 발견한 같은 종류의 무시 파일 3개는 생성된 결과 요약입니다.

따라서 **핵심 구현의 파일 누락은 확인되지 않았습니다.** 다만 파일이 모두 있다는 것이 원문과 바이트 단위로 동일하다는 뜻은 아닙니다. 개인 식별값을 합성값으로 바꾸고, 환경 설정의 부모 경로 탐색을 차단하고, 대시보드 아이콘을 라이선스가 확인된 자료로 바꾸는 등 [공개용 수정](../PUBLIC_RELEASE.md)을 적용했습니다.

## 더 남길 수 있었던 기술 설명

개인 운영 문서 27개를 원문 그대로 배포하지 않는 대신, 공개 구현으로 확인할 수 있는 계좌별 상태 분리, 주문 재시도 구분, 작업 시간 제한, 데이터 신선도와 누락 구분, 연구 후보 승인 원칙을 [설계 결정](DESIGN_DECISIONS.md)에 정리했습니다. [API 사용 방식](API_USAGE.md)도 별도 문서로 추가했습니다.

## 계속 제외하는 자료

| 제외 범위 | 이유 | 공개본에서 제공하는 대안 |
|---|---|---|
| 인증값·계좌 식별자·개인 설정 | 개인 접근 권한과 운영 환경 | 합성 예제, 설정을 읽는 코드 |
| 잔고·주문·손익·개인 사건 기록 | 개인 금융·운영 정보 | 처리 로직, 합성 테스트, 일반화한 설계 설명 |
| 수집 시세·마스터 파일·연구 산출물 | 데이터 권리와 개인 실험 결과를 코드 권리와 분리 | 수집·변환·검사·리플레이 코드 |
| 출처·라이선스 검토가 안 된 에이전트 패키지 | 공개 가능 근거 미확인 | 검토된 패키지만 기존 고지와 함께 포함 |
| 별도 미니앱·디자인 내보내기·운영 스크린샷 | 별도 제품 범위, 자료 권리와 개인정보 | 합성 대시보드와 라이선스가 확인된 아이콘 |
| 기존 Git 이력·브랜치·협업 기록 | 삭제 전 정보와 개인 작업 이력이 남을 수 있음 | 독립된 새 Git 이력 |
| 별도 로컬 연구 서비스 | 이 소스 배포본 밖의 구성요소 | 어댑터·요청 코드와 연결 경계 설명 |

## 이 검토가 뜻하는 범위

현재 주 프로젝트의 관리 대상 핵심 구현을 모두 담았다는 확인입니다. 모든 과거 브랜치·초안·외부 구성요소까지 빠짐없이 공개할 수 있다는 보증이나 모든 저작권·개인정보 문제의 부재를 증명하는 검토는 아닙니다. 외부 자료는 권리 근거를 확보한 뒤 추가할 수 있습니다.

현재 배포 파일 목록은 [PUBLIC_MANIFEST.json](../PUBLIC_MANIFEST.json), 외부 라이선스는 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)를 기준으로 확인하세요.
